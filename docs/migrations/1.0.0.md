# Migrating to SwiftBets.Contracts 1.0.0

1.0.0 declares the contracts stable and starts the V1-to-V2 coupon move. It is source and binary compatible with 0.9.0: `EventEnvelope<T>.Context` is an init property and `Create` keeps its old overload, so packages built against 0.x (building-blocks 0.7.0 included) keep working and consumers can move one at a time.

## What changed

| Change | Effect on consumers |
|---|---|
| `EventEnvelope<T>.Context` (`EventContext`: brand, country, channel) | `Create` always writes it, defaulting to `EventContext.Platform`. Envelopes written before 1.0.0 read with `Context == null`; use `ContextOrPlatform`. Pass a customer's context where the producer knows it. |
| `CouponPlacedV2` on `placement.coupon-placed.v2` | Legs carry `IsBanker`; a coupon holds one or more bets, each a set of fold sizes over the non-banker legs. `SystemBets` gives the lines so placement and settlement agree. |
| `CouponSettledV2` on `settlement.coupon-settled.v2` | Per-bet outcome, line counts and return; the coupon's `TargetPayout` is their sum. |

## Dual-run window

- Placement publishes `CouponPlacedV1` and `CouponPlacedV2` for every coupon a V1 shape can describe (singles and accumulators without bankers), and V2 only otherwise.
- Settlement consumes V2 and publishes `CouponSettledV1` beside `CouponSettledV2` while any V1 consumer remains.

| Consumer | Reads today | Moves to |
|---|---|---|
| settlement | `CouponPlacedV1` | `CouponPlacedV2` |
| payout | `CouponSettledV1` | `CouponSettledV2` |
| history, realtime, risk, steward | `CouponPlacedV1` / `CouponSettledV1` | V2 |

## Removal (2.0.0)

`CouponPlacedV1`, `CouponSettledV1`, their topics and `swiftbets.wallet.v1` go when every consumer above reads V2, no open coupon was placed only as V1, and a full settlement cycle has run on V2 alone.
